# Audio formats

Byte layouts Eyefinder implements, with their sources. Little-endian unless stated. See
[SUPPORT.md](SUPPORT.md) for how far each one is confirmed.

## GTA III and Vice City

### Stream tables
The games open streams by index into a fixed table (`StreamedNameTable` in re3 / reVC
`src/audio/sampman.h`), named by the `eStreamedSounds` enum (`audio_enums.h`). The tables in
`crates/ef-audio/src/tables/` are generated by `tools/gen_tables.py`. It runs the C preprocessor
over those declarations with each build's defines and pairs the n-th file with the n-th enum value.

| Table | Entries | Unique files |
|---|---|---|
| GTA III PC | 196 | 195 (the MP3-player slot reuses `HEAD.WAV`) |
| GTA III PS2 (`.VB` only) | 94 | 94 |
| Vice City PC | 1224 | 1219 (unused slots reuse `MISCOM.MP3`) |
| Vice City PS2 (`.VB` only) | 99 | 99 |

Radio station names are read from `TEXT\AMERICAN.GXT`, keys `FEA_FM0`…`FEA_FM8`.

### GXT (GTA III, Vice City)
A sequence of chunks `{char magic[4]; u32 size; u8 data[size]}`. The main table is the first
`TKEY` (12-byte entries `{u32 offset_into_TDAT; char key[8]}`) plus the first `TDAT` (UTF-16LE,
NUL-terminated strings). Vice City adds a `TABL` chunk first. Source: re3 / reVC `src/text/Text.cpp`.

### PC streams
Detected from content:
* RIFF/WAVE: PCM (copied bit-exact), IMA ADPCM `0x0011`, Xbox ADPCM `0x0069` (decoded as IMA, as re3 does), MS ADPCM `0x0002`, MPEG in RIFF `0x0050`/`0x0055`.
* Raw MPEG audio.

IMA ADPCM uses the reference shift-add nibble expansion, and each block's header sample is output (Microsoft *Multimedia Standards Update*, re3 `CImaADPCMDecoder`). Output is trimmed to the `fact` chunk length. `cue `, `LIST/adtl` and `smpl` chunks are read, kept in the output, and used to write per-marker track files.

### Vice City `.ADF`
MPEG audio with every byte XOR `0x22`. Source: reVC `sampman_miles.cpp`, `vfs_read_callback`.

### `SFX.SDT` / `SFX.RAW` (PC)
`SFX.SDT` is an array of `{i32 offset; u32 size; i32 frequency; i32 loop_start; i32 loop_end}`
(20 bytes) into `SFX.RAW`, which holds 16-bit mono PCM. Loop points are byte offsets; re3 divides
them by 2. `loop_end = -1` means the end of the sample. Sample names come from `eSfxSample`
(`AudioSamples.h`) and are used only when the entry count matches exactly (3032 for GTA III PC).

### PS2 `.VB`
Headerless Sony PS-ADPCM: 16-byte frames of 28 samples, channels interleaved in 0x2000-byte
blocks, always opened as stereo (re3/reVC `CVbFile`). Trailing bytes that do not fill a block are
ignored, as the game does.

The sample rate comes from the game, not the file: 32000 Hz, except 16000 Hz for
`IsThisTrackAt16KHz` tracks (GTA III: `RADIO_CHAT`; Vice City: `RADIO_KCHAT`, `RADIO_VCPR`,
`RADIO_POLICE`).

Decoding follows vgmstream `decode_psx`:
* coefficient pairs 0, 60/64, (115, −52)/64, (98, −55)/64, (122, −60)/64
* shift > 12 is treated as 9, filter > 4 as 0
* flag 7 produces silent samples

### Movies (PC)
MPEG-1/2 program streams. Audio stream ids `0xC0`–`0xDF` are demuxed (ISO/IEC 11172-1 / 13818-1 PES
syntax), saved untouched as `.original.mp2`, and decoded. The first PTS is recorded.

## San Andreas (PC)
Source: gta-reversed `source/game_sa/Audio/Loaders`.

* `AUDIO\CONFIG\STRMPAKS.DAT`: `char name[16]` per stream pack.
* `AUDIO\CONFIG\TRAKLKUP.DAT`: `{u8 pack; u8 pad[3]; u32 offset; u32 size}` per track.
* `AUDIO\STREAMS\<pack>`: each byte XOR `KEY[file_offset & 15]` with
  `KEY = EA 3A C4 A1 9A A8 14 F3 48 B0 D7 23 9D E8 FF F1` (`CAEStreamTransformer`).
  A track starts with `tTrackInfo` (0x1F84 bytes: 1000 × `{u32 m_nTime; u32 m_nKey}`, then
  `u32 field_1F40[16]` and `u16 field_1F80`), followed by an Ogg Vorbis stream. Eyefinder
  checks for `OggS` after the header and exports the header as `.trackinfo.json`. The meaning of
  the beat values is not documented, so they are exported raw under gta-reversed's field names.
* `AUDIO\CONFIG\PAKFILES.DAT`: `{char name[12]; u32 lsn[10]}` (52 bytes) per SFX pak.
* `AUDIO\CONFIG\BANKLKUP.DAT`: `{u8 pak; u8 pad[3]; u32 offset; u32 bytes}` per bank.
* A bank in `AUDIO\SFX\<pak>` at `offset`: `{i16 count; i16 pad; 400 × {u32 offset; u32 loop_start; u16 rate; i16 headroom}}` (0x12C4 bytes), then `bytes` bytes of 16-bit mono PCM. A sound runs from its offset to the next sound's offset, or to `bytes` for the last one. Banks with an inconsistent header are reported and skipped.

## Decoding policy
* MPEG audio: no gapless trimming, because the encoder delay/padding tag is not normative and Miles plays every frame. Delay and padding are reported in the manifest.
* Ogg Vorbis: granule-position trimming is applied, because it is normative.
* MPEG audio and Vorbis decode to 32-bit float by default (16-bit optional).
* ADPCM decodes to 16-bit, its exact output.
* PCM is copied bit-exact.
* Nothing is resampled.
