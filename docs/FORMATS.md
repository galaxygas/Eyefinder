# Formats

Byte layouts Eyefinder implements, with their sources. Little-endian unless stated. See
[SUPPORT.md](SUPPORT.md) for how far each one is confirmed.

# Audio

## GTA III and Vice City

### Stream tables
The games open streams by index into a fixed table (`StreamedNameTable` in re3 / reVC
`src/audio/sampman.h`), named by the `eStreamedSounds` enum (`audio_enums.h`). The tables in
`crates/ef-audio/src/tables/` are generated by `tools/gen_tables.py`. It runs the C preprocessor
over those declarations with each build's defines and pairs the n-th file with the n-th enum value.

| Table | Entries | Unique files |
|---|---|---|
| GTA III PC | 196 | 195 (the MP3-player slot reuses `HEAD.WAV`) |
| GTA III PS2 (`.VB` only) | 94 | 94 |
| Vice City PC | 1224 | 1219 (unused slots reuse `MISCOM.MP3`) |
| Vice City PS2 (`.VB` only) | 99 | 99 |

Radio station names are read from `TEXT\AMERICAN.GXT`, keys `FEA_FM0`…`FEA_FM8`.

### GXT (GTA III, Vice City)
A sequence of chunks `{char magic[4]; u32 size; u8 data[size]}`. The main table is the first
`TKEY` (12-byte entries `{u32 offset_into_TDAT; char key[8]}`) plus the first `TDAT` (UTF-16LE,
NUL-terminated strings). Vice City adds a `TABL` chunk first. Source: re3 / reVC `src/text/Text.cpp`.

### PC streams
Detected from content:
* RIFF/WAVE: PCM (copied bit-exact), IMA ADPCM `0x0011`, Xbox ADPCM `0x0069` (decoded as IMA, as re3 does), MS ADPCM `0x0002`, MPEG in RIFF `0x0050`/`0x0055`.
* Raw MPEG audio.

IMA ADPCM uses the reference shift-add nibble expansion, and each block's header sample is output (Microsoft *Multimedia Standards Update*, re3 `CImaADPCMDecoder`). Output is trimmed to the `fact` chunk length. `cue `, `LIST/adtl` and `smpl` chunks are read, kept in the output, and used to write per-marker track files.

### Vice City `.ADF`
MPEG audio with every byte XOR `0x22`. Source: reVC `sampman_miles.cpp`, `vfs_read_callback`.

### `SFX.SDT` / `SFX.RAW` (PC)
`SFX.SDT` is an array of `{i32 offset; u32 size; i32 frequency; i32 loop_start; i32 loop_end}`
(20 bytes) into `SFX.RAW`, which holds 16-bit mono PCM. Loop points are byte offsets; re3 divides
them by 2. `loop_end = -1` means the end of the sample. Sample names come from `eSfxSample`
(`AudioSamples.h`) and are used only when the entry count matches exactly (3032 for GTA III PC).

### PS2 `.VB`
Headerless Sony PS-ADPCM: 16-byte frames of 28 samples, channels interleaved in 0x2000-byte
blocks, always opened as stereo (re3/reVC `CVbFile`). Trailing bytes that do not fill a block are
ignored, as the game does.

The sample rate comes from the game, not the file: 32000 Hz, except 16000 Hz for
`IsThisTrackAt16KHz` tracks (GTA III: `RADIO_CHAT`; Vice City: `RADIO_KCHAT`, `RADIO_VCPR`,
`RADIO_POLICE`).

Decoding follows vgmstream `decode_psx`:
* coefficient pairs 0, 60/64, (115, −52)/64, (98, −55)/64, (122, −60)/64
* shift > 12 is treated as 9, filter > 4 as 0
* flag 7 produces silent samples

### Movies (PC)
MPEG-1/2 program streams. Audio stream ids `0xC0`–`0xDF` are demuxed (ISO/IEC 11172-1 / 13818-1 PES
syntax), saved untouched as `.original.mp2`, and decoded. The first PTS is recorded.

## San Andreas (PC)
Source: gta-reversed `source/game_sa/Audio/Loaders`.

* `AUDIO\CONFIG\STRMPAKS.DAT`: `char name[16]` per stream pack.
* `AUDIO\CONFIG\TRAKLKUP.DAT`: `{u8 pack; u8 pad[3]; u32 offset; u32 size}` per track.
* `AUDIO\STREAMS\<pack>`: each byte XOR `KEY[file_offset & 15]` with
  `KEY = EA 3A C4 A1 9A A8 14 F3 48 B0 D7 23 9D E8 FF F1` (`CAEStreamTransformer`).
  A track starts with `tTrackInfo` (0x1F84 bytes: 1000 × `{u32 m_nTime; u32 m_nKey}`, then
  `u32 field_1F40[16]` and `u16 field_1F80`), followed by an Ogg Vorbis stream. Eyefinder
  checks for `OggS` after the header and exports the header as `.trackinfo.json`. The meaning of
  the beat values is not documented, so they are exported raw under gta-reversed's field names.
* `AUDIO\CONFIG\PAKFILES.DAT`: `{char name[12]; u32 lsn[10]}` (52 bytes) per SFX pak.
* `AUDIO\CONFIG\BANKLKUP.DAT`: `{u8 pak; u8 pad[3]; u32 offset; u32 bytes}` per bank.
* A bank in `AUDIO\SFX\<pak>` at `offset`: `{i16 count; i16 pad; 400 × {u32 offset; u32 loop_start; u16 rate; i16 headroom}}` (0x12C4 bytes), then `bytes` bytes of 16-bit mono PCM. A sound runs from its offset to the next sound's offset, or to `bytes` for the last one. Banks with an inconsistent header are reported and skipped.

## Decoding policy
* MPEG audio: no gapless trimming, because the encoder delay/padding tag is not normative and Miles plays every frame. Delay and padding are reported in the manifest.
* Ogg Vorbis: granule-position trimming is applied, because it is normative.
* MPEG audio and Vorbis decode to 32-bit float by default (16-bit optional).
* ADPCM decodes to 16-bit, its exact output.
* PCM is copied bit-exact.
* Nothing is resampled.

# Containers and textures

Every layout below is cited, and has fixture coverage in `crates/ef-texture/tests` against the references in `tools/txd-ref`. Sources:
* **librw:** `aap/librw` at commit `18532c2e`, MIT licence.
* **re3:** `src/core`.
* **gta-reversed:** `source/game_sa`.
* **gtamods wiki:** pages "RenderWare binary stream file", "Texture Dictionary", "Texture Native Struct", "IMG archive", "RenderWare Version".

## IMG archives (`ef_core::img`)
* **Version 1 (GTA III, Vice City)**
  * The data is in `name.img`; the directory is a separate `name.dir`.
  * Each directory entry is 32 bytes: `{u32 offset; u32 size; char name[24]}`. Offsets and sizes are in 2048-byte sectors.
  * Sources: re3 `Directory.h` and `CdStream.h` (`CDSTREAM_SECTOR_SIZE`), and `CStreaming::LoadCdDirectory`, which asserts the 32-byte entry size.
* **Version 2 (San Andreas)**
  * Layout: `"VER2"`, `u32 count`, then `count` entries of `{u32 offset; u16 streamingSize; u16 sizeInArchive; char name[24]}`.
  * The size is `sizeInArchive` when it is non-zero, otherwise `streamingSize` (gta-reversed `CStreaming::LoadCdDirectory`).
* Archives are recognised by content: the `VER2` magic, or a `.dir` file next to the `.img`. Eyefinder assumes no list of archive names.
* **Xbox:** gtamods describes LZO-compressed entries in Xbox archives. No source code confirms this, so Eyefinder does not decompress them.

## RenderWare streams
* **Chunk header:** `{u32 type; u32 size; u32 libraryIdStamp}`, where `size` counts the payload including children (librw `base.cpp`).
* **Version stamp:**
  * A stamp with bits set in its high 16 is new-style: `version = ((stamp >> 14 & 0x3FF00) + 0x30000) | (stamp >> 16 & 0x3F)`.
  * Otherwise the stamp is old-style and `version = stamp << 8` (librw `rwbase.h` `libraryIDUnpack`).
  * Examples: 3.6.0.3 is stored as `0x1803FFFF`, 3.1.0.0 as `0x00000310`.
* **Texture dictionary** (chunk `0x16`):
  * A struct `{u16 count; u16 device}`, then `count` TextureNative chunks (`0x15`), then an extension.
  * The first `u32` of each native's struct gives its platform: 8 = Direct3D 8, 9 = Direct3D 9, 5 = Xbox, `PS2\0` = PlayStation 2 (librw `texture.cpp`).

## Texture natives
Raster format bits (librw `rwobjects.h`):

| Value | Format |
|---|---|
| `0x100` | C1555 |
| `0x200` | C565 |
| `0x300` | C4444 |
| `0x400` | LUM8 |
| `0x500` | C8888 |
| `0x600` | C888 |
| `0xA00` | C555 |
| `0x2000` | PAL8 flag |
| `0x4000` | PAL4 flag |
| `0x8000` | MIPMAP flag |

**Direct3D 8 and 9 (PC)** (librw `d3d8.cpp` / `d3d9.cpp` `readNativeTexture`). An 88-byte header:

| Offset | Field |
|---|---|
| 0 | platform |
| 4 | filter / addressing |
| 8 | `char name[32]` |
| 40 | `char mask[32]` |
| 72 | raster format |
| 76 | D3D8: `hasAlpha`; D3D9: `D3DFORMAT` or FourCC |
| 80 | `u16 width` |
| 82 | `u16 height` |
| 84 | `u8 depth` |
| 85 | `u8 levels` |
| 86 | `u8 type` |
| 87 | D3D8: compression 1–5 = DXT1–5; D3D9: flags (bit 0 alpha, bit 1 cube, bit 3 compressed) |

* **Palette:** palettised rasters store 1024 bytes (PAL8) or 128 bytes (PAL4, 16 entries used), as `PALETTEENTRY` R, G, B, alpha. Texels use one byte each, even for PAL4.
* **Levels:** each mip level is a `u32 size` followed by its bytes. Only the first level is read unless the raster has the MIPMAP flag.
* **Uncompressed texels:** Microsoft `D3DFORMAT` A1R5G5B5, R5G6B5, A4R4G4B4, L8, A8R8G8B8, X8R8G8B8 and X1R5G5B5, little-endian. For uncompressed D3D9 textures Eyefinder, like librw, uses the raster format and not the stored `D3DFORMAT`.
* **Not decoded:**
  * D3D9 cube textures, which librw also refuses.
  * DXT2 and DXT4 (premultiplied alpha).

**Xbox** (librw `xbox.cpp`):
* The stream must be at least RenderWare 3.4.0.1.
* The header matches D3D up to offset 72, then:

| Offset | Field |
|---|---|
| 72 | raster format |
| 76 | `i16 hasAlpha` |
| 78 | `i16` unknown, must be 0 |
| 80 | width |
| 82 | height |
| 84 | depth |
| 85 | levels |
| 86 | type |
| 87 | `D3DFMT` (`0x0C` DXT1, `0x0E` DXT3, `0x0F` DXT5, `rwxbox.h`) |
| 88 | `u32 totalSize` |

* **Palette:** stored B, G, R, A.
* **Levels:** stored back to back, each with its computed size.
* **Swizzling:** uncompressed levels are swizzled. Texel (x, y) sits at the index whose bits interleave x and y, starting with x, for as long as both still have bits (librw `unswizzle`).
* **Decoded:** C1555, C555, C8888, the palettes, and DXT1/3/5.
* **Not decoded:** the other pixel formats, because no reference decoder exists to check them against.

**PlayStation 2** (librw `ps2raster.cpp`):
* **Layout:** the native holds:
  * a struct `{'PS2\0', filter}`;
  * the name and mask strings;
  * a struct containing a 64-byte raster header (`StreamRasterExt`), then a struct of texel and palette data.
* **Header fields:**

| Offset | Field |
|---|---|
| 0 | `i32 width` |
| 4 | `i32 height` |
| 8 | `i32 depth` |
| 12 | `u16 format` |
| 14 | `i16 version` |
| 16 | `u64 TEX0` |
| 24 | palette offset |
| 28 | `tex1low` (number of mip levels − 1 in bits 2+) |
| 32 | MIPTBP1 |
| 40 | MIPTBP2 |
| 48 | pixel size |
| 52 | palette size |
| 56 | total size |
| 60 | KL |

* **Header `version` ≥ 2:**
  * Every level and the palette is preceded by a 0x50-byte GIF packet.
  * A level occupies `ALIGN16(w′·h′·depth/8)`, where w′ and h′ are the level size raised to the GS transfer minimum (`transferMinSize`).
  * Eyefinder checks that the levels add up to the header's pixel size and otherwise offers only the first level.
* **Header `version` 0/1:** the texels start the data and the palette follows at the pixel size. Only the first level's position is documented.
* **Swizzling:**
  * 8-bit texels are swizzled in new-style rasters and in version 1.
  * 4-bit texels are swizzled in new-style rasters from RenderWare 3.1.0.1 on.
  * The unswizzle follows librw `swizzle()` / `unswizzleRaster`: bands of 4 rows, row pitch the next power of two of the padded width.
* **Palettes:**
  * 8-bit palettes are in CSM1 order: entries 8–15 and 16–23 of every 32 are exchanged (librw `convertCSM1_32`).
  * 4-bit palettes use their first 16 entries.
* **Colours:**
  * 32-bit colours are RGBA, with alpha `0x80` = opaque (librw: `a·255/128`). Values above `0x80` are treated as opaque.
  * 16-bit colours are A1B5G5R5, red in the low bits.
* **Decoded:** palettes of 32-bit colours, C8888 and C1555.
* **Not decoded:**
  * 16-bit palettes: librw does not convert them, so their CLUT layout is unconfirmed.
  * C888 rasters.

## Colour conversion
* Every stored channel is converted to 8 bits with one rule. Its value is `stored / max` as the format defines it, rounded to the nearest 8-bit step, ties up (Vulkan specification, "Conversion From Floating-Point to Normalized Fixed-Point").
  * Each 8-bit result therefore identifies its stored value uniquely.
  * The `.dds` export keeps compressed data untouched.
* **S3TC** (DXT1, DXT3, DXT5) follows the Khronos Data Format Specification 1.3, "S3TC Compressed Texture Image Formats", including that BC2 and BC3 colour blocks always use the four-colour encoding.
  * DXT1 is opaque when the raster format is C565 (PC) or `hasAlpha` is 0 (Xbox), as in librw.
* **Differences from the other decoders:**
  * librw and Pillow truncate instead of rounding, so they differ from Eyefinder by at most 1 per channel (2 for S3TC, where they truncate twice). `tools/txd-ref/make_reference.py` checks that bound on every fixture.
  * librw also differs from the specifications in three places: its D3D palette path reads indices two texels ahead, its DXT5 colour block uses the DXT1 three-colour mode, and its Xbox path keeps the unused top bit of X1R5G5B5 as alpha. Eyefinder follows the specifications in all three.

# Game versions (`ef_core::edition`)
* **PC:** DK22Pac plugin-sdk `shared/GameVersion.cpp` (commit `15f15b60`) identifies each executable by one 32-bit value at a fixed virtual address.
  * Eyefinder reads that value from the file, mapping the address through the PE section table (Microsoft "PE Format").
  * Executables that are packed or encrypted on disk are reported as unknown.
  * Executable names: `gta3.exe`, `gta-vc.exe`, `gta_sa.exe` (retail), `gta-sa.exe` (Steam).
* **PS2:** the serial is the boot file named by `BOOT2` in `SYSTEM.CNF` (PCSX2 `ExecutablePathToSerial`). It is looked up in PCSX2 `GameIndex.yaml` (commit `5b6e6e23`).

## GTA1 / London PC sample banks

Source: Daniel Marschall's firsthand [SDT analysis](https://misc.daniel-marschall.de/spiele/gta1/format_sdt.html)
and [retail inventory](https://misc.daniel-marschall.de/spiele/gta1/files/index.html),
corroborated for record layout and bit depth by OpenGTA
`1ae34ae3409d37bf484364d2a1db2e183a8527bd`, `read_sdt.cpp` and `util/sound_fx_cache.cpp`.

* `GTADATA/AUDIO/*.SDT`: consecutive `{u32 offset, u32 length, u32 sample_rate}`
  records into the same-stem `.RAW`. Only documented audio banks are interpreted;
  graphics `.RAW` files are never treated as audio.
* `LEVEL000`: signed little-endian 16-bit PCM; entries 0–2 stereo, subsequent entries mono.
* `LEVEL001`, `LEVEL002`, `LEVEL003`, `MISBRIEF`, `VOCALCOM`: unsigned 8-bit mono PCM.
* London uses `GTADATA/UK/AUDIO`; `LEVEL002/003` in that subtree are GTA1 leftovers
  and are excluded. The shared layout does not identify 1969 versus 1961: users must
  choose the expansion. Neither executable version nor complete expansion coverage
  is inferred from these bank names.
* Truncated index records, zero rates, out-of-file ranges and partial PCM frames
  reject the bank with a catalog notice. Empty entries are skipped. PCM bytes are
  preserved without resampling; loose WAVs use the existing content-based reader.
* Synthetic fixtures include all three channel/depth combinations and nonzero
  bank offsets, compared with ffmpeg PCM output and exact-seek tests.

## GTA2 PC sample banks

Source: [gta2_re](https://github.com/CriminalRETeam/gta2_re/tree/edb484d3b71d5cadaf3a9ea0e435f56993c747e7),
`cSampleManager.hpp::sdt_entry_0x18`, `cSampleManager.cpp::LoadWavSdtData_58E980`,
`AllocSamples_58D9F0` and `InitialiseChannel3D_58DDF0`. Only layout facts are used;
no source code is copied.

`DATA/AUDIO/<style>.SDT` has **24-byte** records of six little-endian signed 32-bit
fields: offset, length, playback rate, random displacement, loop start, loop end.
Companion RAW samples are signed 16-bit mono PCM (Miles format 1, flags 1).
Random displacement is preserved as metadata; export uses the stored playback rate.
Loop byte offsets and the `-1` end sentinel are preserved. `DATA/FSTYLE.STY` and its
frontend audio bank identify the PC layout. Loose WAVs in the audio subtree are
also catalogued. Synthetic sample references are generated with ffmpeg.

## DMA style textures (GTA1 / London PC)

Sources: DMA Design, [CityScape Data Structure 12.10](https://misc.daniel-marschall.de/spiele/gta1/cds.pdf),
sections 3.3–3.8; OpenGTA at the revision above, `read_gry.cpp`, `read_g24.cpp`.
The GRY version contradiction in the document is resolved in favor of **325**, the
version actually accepted by OpenGTA. Version 305 is not silently treated as 325.
G24 is **336**. These are separate containers, not synthetic TXDs.

* GRY header: 13 u32 fields (version plus side/lid/aux/animation/palette/remap/
  remap-index/object/car/sprite-info/sprite-graphics/sprite-number byte sizes).
* G24 header: 16 u32 fields; palette/remap fields are replaced with CLUT size,
  tile/sprite/new-car/font virtual CLUT byte counts and palette-index byte size.
* Tiles are 64×64, indexed 8-bit pixels in 256-pixel-wide strips. The combined tile
  store is padded to a multiple of four tiles, independent of section size fields.
* GRY palette is 256 RGB triples. Remaps contain 256 byte-index permutations;
  each lid has four remap identifiers in the 256×4 remap-index table.
* G24 physical CLUT storage rounds up to 65536 bytes. Physical palette columns
  contain BGRA entries: `(palette/64)*65536 + color*256 + (palette%64)*4`.
  A u16 palette-index table maps virtual to physical palettes. Tile variants use
  `tile*4+variant`; sprite palettes start at `tileclut_size/1024`.
* GRY sprite records are 10 bytes and G24 records are 12: width, height, delta
  count, compression byte, u16 pixel count; G24 adds a u16 palette. The final
  u32 is the byte offset into the 256-pixel-wide sprite store. Each delta adds
  `{u16 size,u32 offset}`. Compressed sprites are rejected.
* Delta streams repeat `{u16 relative_offset,u8 length,u8 pixels[length]}`.
  Offsets use 256-pixel-wide page coordinates. Each stored delta is exported as
  its own modified sprite, retaining transparent erasures.
* Palette index zero is transparent; other indices are opaque. The palette's
  unused fourth byte is not interpreted as ordinary straight alpha.

## GTA2 PC STY

Sources: DMA Design, [GBH Style Format 4.6](https://gtamp.com/gta2/gta2-style-sty-graphics-file-format/),
sections 3–6 and 12; gta2_re at the revision above,
`gtx_0x106C.cpp::LoadSty_5AB750` verifies retail **700**, rather than the older
600 in the published spec. The independent viewer
[izawartka/gta2-sty-viewer-js](https://github.com/izawartka/gta2-sty-viewer-js/tree/582f0eb68d495fdbf6838ec0312e2906d639d1f1)
also accepts 700.

* Header `GBST` + u16 version; chunks `{char id[4],u32 size,payload}` to EOF.
  Chunk order is independent; unknown chunks are skipped; duplicates/truncation fail.
* `TILE`: paged 64×64 indexed tiles. `PPAL`: BGRA palette columns as above.
  `PALX`: 16384 u16 virtual-to-physical palette entries. `PALB`: eight u16 counts;
  cumulative counts give the bases, so the first count is the sprite palette base.
* `SPRX`: `{u32 byte_offset,u8 width,u8 height,u16 padding}` into `SPRG` pages.
* `DELX`: `{u16 sprite,u8 count,u8 padding,u16 sizes[count]}`. `DELS` contains the
  corresponding delta streams in sequence. Delta instructions use the layout above.

The shared catalog loads a container-neutral collection. Style images use their own
platform label and RGBA representation; RenderWare version is absent in the UI and
empty in export metadata. PNG preview/export share the same decoding path. No DDS
is fabricated for indexed styles. Tile variants, base sprites and individual stored
deltas are included; sprite remaps, combined delta states and standalone graphics
are explicitly not yet enumerated. New entries remain **FromSpec**.

`tools/txd-ref/build.sh` also generates GRY/G24/STY fixtures and
`style_reference.json`. Expected RGBA is generated separately in image order from
semantic patterns, independently of the parser's offset/page calculations. Fixtures
exercise tile strip crossings/padding, sprite page crossings, the second CLUT page,
remaps, transparent pixels and delta erasures. Catalog-to-PNG round trips compare
with preview pixels; truncated inputs and invalid sizes are rejected.

### GTA1 / London PC FON images

Source: [Daniel Marschall's firsthand FON analysis](https://misc.daniel-marschall.de/spiele/gta1/format_fon.html).
Two header bytes specify the image count and shared height. Each image has one
width byte followed by width × height row-major palette indices. A trailing
256-entry RGB palette occupies 768 bytes. OpenGTA commit
`1ae34ae3409d37bf484364d2a1db2e183a8527bd`, `read_fnt.cpp::getCharacterBitmap`
and `read_gry.cpp::RGBPalette::apply`, establish index-zero transparency.

There is no magic identifier; dispatch requires a `.fon` filename in a GTA1 or
London catalog. Images retain numeric indices, without guessing character maps.
Zero-width images are reported and skipped; malformed/truncated containers fail.
Synthetic variable-width images, spacers, all palette indices, and truncated
inputs are tested against a semantic pixel reference through the regular texture
fixture generators. Catalog previews and PNG export use the same collection.
